# 方案 D 落地：sherpa 服务上的 piper zh + piper en 双模型路由

日期：2026-09-24　服务：`tts-cpu-only/docker-compose.yaml`（sherpa-tts，端口 8000）
目标：**300 字中文 ≤ 2 秒**，且中英混排正确、音色尽量一致。

---

## 1. 结论

| 指标 | 实测 |
| --- | --- |
| 231 字中文（=300 字量级） | **0.71 s**（RTF 0.0134，**74.6× 实时**） |
| 中文 96 字告警 | 0.34 s（60×） |
| 中英混排 | 0.15 s（43×） |
| 英文 82 字 | 0.22 s（26×） |

按此换算，**300 字约 0.9 s，2 秒目标有 2 倍余量**，且中英文都走原生 piper 音色。

## 2. 改动内容

### 2.1 新增音色（`model_weight/`）

| 音色 ID | 模型 | 语言 | 说明 |
| --- | --- | --- | --- |
| `female` | vits-piper-zh_CN-xiao_ya-medium | 中 | 原有 |
| `male` | vits-piper-zh_CN-chaowen-medium | 中 | 原有 |
| `en_female` | vits-piper-en_US-amy-medium | 英 | 新增 |
| `en_male` | vits-piper-en_US-ryan-medium | 英 | 新增 |

四个模型都是 22.05 kHz，**拼接无需重采样**；英文模型用 espeak-ng 前端（`espeak-ng-data`），
中文模型用 lexicon + `phone/date/number.fst`（`vits_tts_server.py` 里按 `kind` 区分构建配置）。

### 2.2 新增模块 `model_app/text_routing.py`

1. `normalize_domain_text()`：电力领域文本规范化（解析依据见下）；
2. `resolve_voice_spans()`：按语种切分并选音色（`voice=auto`）。

### 2.3 `model_app/vits_tts_server.py`

- `VOICE_MODELS` 扩展为 4 个音色，`/health` 返回全部状态与路由配置；
- 新增 `build_chunk_plan()`：`voice=auto` 时先按语种切分，再逐段按标点切句，
  生成 `[(voice_id, sid, sentence)]` 计划；
- `/api/tts`：所有分块（中英混排）统一提交到原有 10 线程池并发合成，**按原顺序拼接**；
- `/api/tts_sse`：按计划逐块推送，`voice_used` 字段会显示该块实际使用的音色；
- 接口保持向后兼容：`{"text","voice","sid","speed"}`，`voice` 现支持
  `male` / `female` / `en_male` / `en_female` / `auto` / `auto:male` / `auto:female`。

调用示例：

```bash
curl -X POST http://127.0.0.1:8000/api/tts -H 'Content-Type: application/json' \
  -d '{"text":"乐园变11F5园开线相间距离I段…","voice":"auto","sid":0,"speed":1.0}' -o out.wav
```

## 3. 电力领域规范化的实测依据

用 ASR 回读逐项验证（原始文本 → 修复后）：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `&#x20;` 被读成「x 二十」，还会误触发英文音色 | HTML 实体 | 实体清理 + 空白收敛 |
| `相间距离I段` 读成「距离 i 段」 | 罗马数字被当字母 I | `I/II/III 段` → 一/二/三段（含全角Ⅰ/Ⅱ） |
| `1.359km` 读成「in 三百五十九」 | **piper 中文 number.fst 处理小数不可靠** | 小数转中文读法 `一点三五九` |
| `7.594A` 丢掉「安」 | 单位未归一 | `A→安`（仅数字后且后面非字母/汉字），另含 kV/kA/MW/MVA/kWh/km/Hz/ms/s/Ω/V |
| `故障相别AC相` 读成「故障相别**箱**」 | 中文音色读字母串会变形 | **纯大写缩写（AC/GPU/FTU/SCADA…）始终路由到英文音色** |
| `请把 GPU 监控数据导出来` 中 **GPU 整段消失** | piper 中文词表无该 token | 同上 |

替换只在**中文语境**生效（向左找最近的汉字/字母判断），纯英文句子完全不受影响，
例如 `The distance is 1.359 km.` 原样保留。

---

## 4. 音色一致性的取舍

- 这类告警文本 99% 是「中文 + 短 token」：`F5`/`km`/`A` 等并入中文音色，
  实测 `voice=auto` 与固定 `female` 输出完全一致（0 次切换）；
- 真正会切换的是两类：**成句英文**（≥ `AUTO_MIN_SPAN_CHARS`，默认 4）和
  **纯大写缩写**（AC/GPU/…）。后者是刻意的：不切就会读错或整段丢失，宁可换 2~3 个字母的音色；
- 若业务要求「一条告警必须同一个声音」，把 `AUTO_MIN_SPAN_CHARS` 调大、
  并把缩写写进领域词表（例如 `AC→A、C 相`、`GPU→图形处理器`）即可完全不切换。

## 7. 试听反馈的 3 个问题与修复（2026-09-28）

### 7.1 中英拼接处静音过长、表述生硬

原因：piper 每个分块自带 0.05~0.3 s 首尾静音，直接拼接后中英/句间停顿叠加；
且原来**句中的语种切换也按标点插停顿**，把 "故障相别AC相" 切成 3 段并各留大停顿。

修复（`vits_tts_server.py`）：

1. **裁掉分块首尾静音**（`trim_silence`，只裁边缘、保留 25 ms 余量），
   实测每块头/尾静音从 50~300 ms 降到 **4~27 ms**；
2. **按标点分级插入停顿**：句末 120 ms / 逗号等 50 ms / 句中语种切换 **20 ms**；
3. **边缘 8 ms 淡化**，消除拼接 click；
4. **合并相邻句子成 ≤80 字的块**（`CHUNK_MAX_CHARS`）：231 字长文从 ~10 块降到 **2 块**，
   块内韵律交给模型自己处理，拼接点大幅减少。

实测停顿（>60 ms 的停顿即为模型自身的标点停顿，已无 0.2 s 以上的拼接空洞）。

### 7.2 单个英文字符（A/B/C 相、11F5 中的 F）不发声

原因：piper 中文词表里**没有拉丁字符**，中文音色遇到字母直接丢弃（静音）。
之前的规则只把「≥2 个大写字母的缩写」路由到英文音色，单个字母仍留在中文片段 → 被吞掉。

修复：**任何含字母的片段都不再并入中文片段**，一律交给英文音色；
同时把「字母+数字」混合 token 拆开并转中文数字：

| 原文 | 修复后 |
| --- | --- |
| `故障相别AC相` | `故障相别` + `AC`(英) + `相` —— A、C 读出 |
| `A相电压` | `A`(英) + `相电压` —— A 读出 |
| `乐园变11F5园开线` | `乐园变十一` + `F`(英) + `五园开线` |
| `AC380V进线` | `AC`(英) + `三百八十伏进线` |

ASR 回读验证：`故障相别 ac 幺 … 二次之 a 相七点五九四安 a 向九点三一三安`（字母已发声）。

### 7.3 常见符号 → 汉字字典

新增符号映射（仅中文语境生效，纯英文句子不受影响）：

| 符号 | 读法 | 示例 |
| --- | --- | --- |
| `℃` `°C` / `℉` `°F` | 摄氏度 / 华氏度 | `25.3℃` → 二十五点三摄氏度 |
| `%` `‰` | 百分之 / 千分之（前置于数字） | `30%` → 百分之30（读作「百分之三十」） |
| `±` | 正负 | `±1.5%` → 正负百分之一点五 |
| `°` | 度 | `45°` → 45度 |
| `Ω` `V` `A` `kV` `kA` `MW` `MVA` `kWh` `km` `Hz` `ms` `s` | 欧姆/伏/安/千伏… | `220.5kV` → 二百二十点五千伏 |
| `×` `÷` `·` | 乘/除/点 | `2×3` → 2乘3 |
| `≤` `≥` `≈` `≠` | 小于等于/大于等于/约等于/不等于 | |
| `~` `～` `→` `←` | 到 | `5~10米` → 5到10米 |
| `#` `№` | 号（后置于数字） | `#2主变` → 2号主变 |
| `&` `@` `μ` `²` `³` `√` `∞` | 和/艾特/微/平方/立方/根号/无穷 | |

### 7.4 可调参数（`docker-compose.yaml`）

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |

## 8. 改用「大写字母/缩写 → 中文近似读法」（2026-09-28 二轮）

### 8.1 思路

试听后反馈「字母用英文音色读会有音色跳动」。改为：

- **大写字母与缩写**（A 相、AC、GPU、SCADA、FTU、11F5 里的 F…）→ **用中文近似音读**，
  由中文音色读出来，音色完全统一；
- **真正的英文单词/句子**（含小写字母，例如 `tell me the status of the system.`）→ 仍然路由到英文音色。

| --- | --- | --- | --- | --- | --- | --- | --- |
| A | 诶 | H | 艾尺 | O | 欧 | V | 维 |
| B | 必 | I | 爱 | P | 皮 | W | 达布留 |
| C | 西 | J | 杰 | Q | 丘 | X | 艾克斯 |
| D | 迪 | K | 开 | R | 阿尔 | Y | 歪 |

### 8.3 实测效果（ASR 回读 + 音色使用日志）

| 文本 | 规范化结果 | 音色使用 | ASR 回读 |
| --- | --- | --- | --- |
| 故障相别AC相，请检查A相电压。 | 故障相别诶西相，请检查诶相电压。 | 仅 female（1 块） | 故障箱别 **a c** 箱请检查 **a** 相电压 |
| SCADA 系统告警，FTU 通信中断 | 艾丝西诶迪诶 系统告警，艾弗提优 通信中断 | 仅 female | **艾思希 a da** 系统告警**埃弗提优**通信中断 |

231 字 → **1.03 s（49× 实时）**；96 字告警文本（20 s 音频）→ 0.65 s。与上一版持平。

## 9. 试听二轮反馈的 2 个问题（2026-09-28 三轮）

### 9.1 `一次设备 QF、QS 位置` 中，`、` 后面的 QS 被路由到英文音色

原因：判断「是否中文语境」用的是**逐字符向左找最近的汉字/字母**，
而 `QS` 左边第一个字母是前一个缩写 `QF` 的 `F` → 被误判成英文语境 → 不转中文、走英文音色。

修复：改为**窗口内汉字占比判断**（±20 字窗口，汉字存在且 `汉字*4 ≥ 字母数` 视为中文语境）。

| 文本 | 修复后 | 音色 |
| --- | --- | --- |
| 一次设备 QF、QS 位置 | 一次设备 丘艾弗、丘艾丝 位置 | 仅 female，0 次切换 |
| The QF、QS status is unknown. | 原样（英文句） | en_female |

### 9.2 `III` 被读成三个「艾」（罗马数字没有生效）

原因：旧规则**只处理 `I/II/III 段`**（必须跟着"段"字），
其它位置的罗马数字（`III母`、`第III部分`）会落到字母名映射，被逐字母读成「爱爱爱」。

修复：改为**通用罗马数字识别**（含全角 Ⅰ/Ⅱ/Ⅲ/Ⅳ…），只要处于中文语境就转中文数字；
单个 `I`/`V` 必须后跟领域后缀（段/母/类/次/号/级/侧/线/回/路/组/套/部分/间隔/象限）才转换，
避免误伤字母（`V相` 仍读字母 V、`I/O` 仍读字母）。

| 文本 | 修复后 |
| --- | --- |
| III母、IV母 | 三母、四母 |
| 第III部分设备 | 第三部分设备 |
| Ⅰ母、Ⅱ母 | 一母、二母 |
| 相间距离I段、零序过流II段 | 相间距离一段、零序过流二段 |
| V相电压 | 维相电压（字母 V，不是罗马数字） |
| I/O 模块 | 爱/欧 模块（字母） |

### 9.3 关于 `letter_names.json` 与 `text_routing.py` 的优先级

- `model_app/letter_names.json` **优先**：服务启动时读取该文件并覆盖
  `text_routing.py` 里的内置默认表（`_DEFAULT_LETTER_NAMES`），只覆盖文件中出现的键；
- 文件不存在或解析失败时回落到内置表；
- 路径可用环境变量 `LETTER_NAMES_FILE` 指定，另有总开关 `LETTER_NAMES_ZH`；
- 实测：把 JSON 改成 `{"F": "艾夫"}`，则 `F` 读作「艾夫」，未覆盖的 `A` 仍用内置「诶」。

注意：`III` 读错**不是**这个优先级造成的，而是上面 9.2 说的罗马数字规则覆盖不全。
